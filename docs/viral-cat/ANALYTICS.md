# Analytics and experiment plan

The game emits privacy-light client events through:
- `window.dispatchEvent(new CustomEvent("dwm:analytics", ...))`
- `window.gtag(...)` only when an existing gtag implementation is already present

No analytics SDK is added in V1.

## Current events

- `page_view`
- `game_start`
- `fish_stolen` { fish }
- `run_end` { fish, reason, delta }
- `retry`
- `challenge_copy` { fish }
- `share` { fish }
- `share_error`

## Funnel

1. landing
2. first pointer interaction
3. survives first real look
4. first fish
5. first death
6. retry
7. 3rd attempt
8. share / challenge
9. inbound challenge start
10. inbound challenger beats target

## Experiments, in order

### E1 — core readability
A: current fish-drag instruction
B: no text, animated hand hint

Primary metric: first interaction rate.
Guardrail: early accidental-death rate.

### E2 — anticipation
A: 520 ms real warning
B: 380 ms real warning

Primary: retry rate.
Guardrail: rage exits after first death.

### E3 — fake cues
A: 38% fake cues
B: 20% fake cues
C: 50% fake cues

Primary: attempts/session.
Guardrail: time to first fish.

### E4 — result framing
A: "MISO SAW YOU"
B: "0.08s TOO LATE"
C: personality joke

Primary: retry after failure.

### E5 — sharing
A: text/link only
B: generated portrait score card
C: short replay clip (future)

Primary: share completion.
Secondary: inbound challenge starts.

### E6 — art
A: current premium vector
B: lightweight 3D
C: flatter sticker look

Primary: page → first interaction.
Secondary: session length.
Guardrail: LCP / load time.

## Viral coefficient

Track:

`K = shares_per_player × unique_open_rate × challenge_start_rate`

Do not optimize raw share-button clicks. The useful metric is new playable sessions generated by existing players.

## Deployment discipline

Because Vercel deployment quota is limited, do not push iterative visual tweaks to a Vercel-connected branch.

Preferred workflow:
1. batch code changes locally / in a non-production branch
2. run build + tests locally
3. make one remote commit for a coherent iteration
4. create at most one preview deployment for that iteration
5. verify
6. promote the same tested artifact rather than rebuilding where possible
