# 996 传2 → 传3｜AI 辅助 10 工作日迁移冲刺计划

**状态：条件性技术计划。不是承诺10天完成整款游戏上线。**

## 项目边界
线上客户已确认：目标是**可运行的迁移工具**，之后由客户技术团队人工测试与调试。客户声称拥有996传2/传3引擎说明书、合法授权、完整客户端/脚本及数据库资料，但样本和接口尚未实测。现有部分脚本人工转换过，数据库字段映射未完成。
另一次讨论中提到50个NPC功能、80张地图、30套装备、100只怪物素材、单人50天；**这些数字未在此次线上Diagnosis被确认**。需重新核对是否纳入10天范围。

## 开工前 Day 0（不计入十天）
获得两版引擎准确版本号、可运行测试环境、文档、合法授权和访问权限、脱敏角色/装备/货币数据库样本、复杂NPC脚本、3张不同类型地图、1套装备及3种怪物样本；客户需指定验收人员。
明确六项：交付工具或完整游戏、每类功能资源数量、源码/API权限、功能兼容清单、现网玩家历史数据是否迁移、验收责任和通过标准。缺少任一关键材料时，10天倒计时暂不开始。

## 十日排期

| 工作日 | AI辅助开发工作 | 人工关卡 / 当天产物 |
|---|---|---|
| D1 | 多Agent读取传2/传3手册，提取命令/字段/地图/资源差异和清点目录 | 确认授权、范围和版本；输出差异矩阵及样本清单 |
| D2 | 并行验证数据库字段、复杂NPC脚本、地图、怪物装备四类PoC | **Go/No-Go**：若关键格式/API无法转换或必须重写大量逻辑，改为分期实施；输出实测证据 |
| D3 | 生成数据库字段映射、类型转换、关联/数值校验、dry-run | 人工确认关键装备/货币/角色映射；数据转换器v1 |
| D4 | 解析NPC与脚本命令、变量及触发器，生成转换规则和Unsupported清单 | 人工核对3类复杂脚本行为；脚本转换器v1 |
| D5 | 批量转换地图/资源索引、链接与碰撞配置 | 传3测试端实测3张代表地图的显示、传送和碰撞；地图转换器 |
| D6 | 批量处理装备/怪物动画引用、属性和掉落配置 | 验证1套装备、3种怪物的动作、AI与掉落；素材转换器 |
| D7 | 集成CLI、配置、日志、checksum、备份、失败退出码、幂等重跑 | 不触及生产库、原资源只读；统一迁移工具候选版 |
| D8 | 对已证明规则适用的内容批量转换，AI辅助分类异常、给出修复候选 | 人工抽样确认，列出成功/失败/未支持/待人工项 |
| D9 | AI生成回归用例和前后数据差异比较、失败恢复测试 | 客户验收人员实测登录、NPC、地图、装备、战斗、数据一致性；测试记录 |
| D10 | 修复约定的P0/P1问题，生成工具说明和配置、回滚操作手册 | 客户验收**工具可重复执行、可追踪失败**；归档完整交付包和遗留问题 |

## 分工和不可跳过的质量条件
- Agent A：引擎手册、指令差异；Agent B：数据库映射；Agent C：脚本/NPC；Agent D：地图素材与回归。
- 1名工程师做架构、代码审查、集成和实际环境验证；客户至少1名熟悉游戏数据的技术验收者并行配合。
- 转换工具必须具备dry-run、原始数据备份、失败报告、可重复执行和校验功能；不得静默丢失数据/忽略不支持脚本。
- 每类资源输出总数、成功、失败、跳过、人工处理数；文件转换成功不等于玩法正确。
- 10天可承诺的候选交付范围是**迁移工具+样本验证+约定资源的批量转换结果和异常列表**。整款游戏所有玩法、现网历史数据及上线由后续人工测试和另行验收决定。
- 如果 D2 的实证显示大量自定义功能无法映射或缺少目标引擎接口，应调整工期和合同，不强行把未知工作算进10天。

## 对Diagnosis的产品验收标准
必须独立追踪六个关键决策及客户原话证据；填写“无、未知、待定”不得增加完成度。报告分别展示信息完整度、六项确认状态、技术PoC通过与否；不允许将10天目标当成已验证交付承诺。
