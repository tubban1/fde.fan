
做“AI 智能租车报价助手”，最重要的不是让 AI 随口报一个价格，而是建立一套：

> **规则可控、价格可解释、风险可管理、报价可追溯**的智能报价系统。

可以把整个系统拆成四层：

1. 用户需求识别
2. 车辆与库存匹配
3. 报价计算
4. 页面呈现与转化

---

# 一、AI需要收集哪些信息

## 1. 基础租车需求

这是生成报价的最低信息集：

* 取车时间
* 还车时间
* 取车地点
* 还车地点
* 驾驶人数
* 驾驶员年龄
* 驾照签发国家
* 车型需求
* 预计里程
* 是否跨城市、跨省或跨境
* 是否需要送车上门
* 是否需要儿童座椅、雪链、导航等

AI不应一次性丢出十几个问题，而是通过对话渐进询问。

例如：

> 您计划什么时候取车？
> 取车和还车是在同一个城市吗？
> 大约几个人乘坐？行李多不多？

---

## 2. 用户没有明确表达，但AI需要判断的信息

例如用户说：

> 我们一家四口去川西玩七天。

AI需要推导：

* 可能需要SUV
* 可能走山路
* 可能需要较高离地间隙
* 里程较高
* 可能涉及异地还车
* 需要重点提醒轮胎、保险和道路救援

但AI必须把推断说清楚：

> 根据四人、长途及山路场景，我暂时按中型SUV报价。您也可以切换为MPV或经济型轿车。

不能把推断当成用户已经确认的事实。

---

# 二、哪些因素决定最终报价

这里建议区分两套权重：

* **价格组成占比**
* **动态报价影响权重**

这两者不能混在一起。

---

# 三、租车价格的成本组成占比

下面是一套适合普通自驾租车业务的初始模型。实际比例需要根据车队成本和历史订单校准。

| 成本成分          |     建议占比 |
| ------------- | -------: |
| 车辆折旧与资金成本     |      25% |
| 保险、税费、牌照成本    |      12% |
| 保养、维修、轮胎损耗    |       9% |
| 清洁、整备、交付成本    |       7% |
| 停车、门店、场地成本    |       6% |
| 客服、支付、平台及运营成本 |       7% |
| 车辆闲置与库存风险     |      10% |
| 事故、违章、坏账风险准备  |       8% |
| 动态市场与供需调节     |       8% |
| 基础利润          |       8% |
| **合计**        | **100%** |

这张表适合内部财务和定价模型使用，不一定全部显示给顾客。

顾客端可以简化为：

* 基础租金
* 保险保障
* 里程费用
* 取还车服务
* 附加服务
* 税费
* 优惠

---

# 四、动态报价因素及建议权重

AI报价引擎可以先计算一个“标准日租价”，再根据以下因素调整。

| 报价因素        |     建议权重 |
| ----------- | -------: |
| 车型、车龄与车辆价值  |      20% |
| 日期、季节与实时供需  |      18% |
| 租赁时长        |      14% |
| 预计里程与使用强度   |      10% |
| 取还车地点及异地还车  |      10% |
| 保险方案与免赔额    |      10% |
| 驾驶员年龄、驾龄及风险 |       7% |
| 上门送取车成本     |       5% |
| 附加设备与服务     |       3% |
| 渠道优惠、会员等级   |       3% |
| **合计**      | **100%** |

这不是说价格直接由这些百分比相加，而是代表每类因素在动态调整中的影响程度。

---

# 五、推荐的报价公式

可以采用这种结构：

```text
最终报价 =
基础车型价格
× 日期供需系数
× 租期系数
× 驾驶风险系数
+ 里程费用
+ 异地还车费
+ 保险费用
+ 送取车费用
+ 附加服务
+ 税费
- 优惠
```

例如：

```text
基础租金：420元/天 × 5天 = 2,100元
周末供需调整：+8% = 168元
保险升级：300元
预计超里程：160元
上门送车：80元
优惠：-150元

最终报价：2,658元
```

# 六、不同因素如何调整价格

## 1. 租赁时长

建议不是简单“天数越多越贵”，而是阶梯价：

| 租期     | 日租系数 |
| ------ | ---: |
| 1天     | 1.15 |
| 2–3天   | 1.05 |
| 4–7天   | 1.00 |
| 8–15天  | 0.90 |
| 16–30天 | 0.80 |
| 月租     | 单独定价 |

这样长期租赁更有吸引力。

---

## 2. 日期与需求

可以设定动态系数：

* 普通工作日：0.90–1.00
* 普通周末：1.05–1.15
* 节假日：1.20–1.60
* 展会、演唱会、旅游旺季：1.20–1.80
* 临近取车、库存紧张：额外上调

AI需要解释涨价原因，而不是只显示结果：

> 该日期为节假日前一天，同级车辆余量较少，当前价格包含12%的供需调整。

---

## 3. 驾驶员风险

可以考虑：

* 年龄
* 驾龄
* 驾照国家
* 是否首次使用平台
* 是否多人驾驶
* 历史事故与违章
* 支付及信用风险

但这些因素应影响：

* 押金
* 保险要求
* 是否允许租赁
* 部分风险附加费

不建议让AI在没有明示规则的情况下，基于用户职业、性别、民族等属性报价。

---

## 4. 里程

常见三种方案：

### 不限里程

价格更高，适合长途用户。

### 每日限额

例如每天200公里，超过后每公里收费。

### 套餐里程

例如：

* 500公里套餐
* 1,000公里套餐
* 不限里程套餐

AI可以主动计算哪一种更划算：

> 您预计行驶1,200公里，选择不限里程套餐比按超里程收费预计节省260元。

# 七、哪些属于硬规则，不能交给AI自由判断

以下内容必须由规则引擎决定，而不是大模型决定：

* 车辆是否有库存
* 用户年龄是否符合要求
* 驾照是否有效
* 能否跨境
* 能否异地还车
* 车辆是否允许进入特定区域
* 最低押金
* 保险限制
* 营运牌照及法规要求
* 黑名单和风险名单

正确架构应该是：

```text
大模型负责理解用户需求
↓
规则引擎负责资格判断
↓
价格引擎负责计算
↓
大模型负责解释和推荐
```

不是：

```text
用户问AI
↓
AI直接编一个价格
```

# 八、页面最终应该是什么样子

建议采用“对话 + 报价看板”的双栏结构。

---

## 页面顶部

显示：

```text
AI 智能租车报价助手
告诉我你的行程，我会帮你匹配车辆并计算透明报价
```

下面提供快捷入口：

* 商务出行
* 家庭旅游
* 长途自驾
* 婚礼用车
* 机场接送
* 月租用车

---

## 左侧：AI对话区

示例：

> AI：您准备在哪一天、哪个城市取车？
> 用户：8月12日在成都，租7天，去川西。
> AI：几个人乘坐？预计有多少行李？
> 用户：4个人，两个大箱子。
> AI：建议选择中型SUV。我会分别提供经济型、舒适型和高保障三个方案。

对话中可以显示当前已确认条件：

```text
成都取车
租期7天
4人
川西长途
预计1,500公里
```

---

## 右侧：报价结果区

建议一次显示三套方案，而不是只给一个价格。

### 方案一：经济型

```text
大众探岳或同级
总价：3,680元
约526元/天

包含：
基础保险
每日250公里
门店取还车

适合：
预算优先、驾驶经验丰富
```

### 方案二：推荐型

```text
丰田RAV4或同级
总价：4,280元
约611元/天

包含：
加强保险
不限里程
道路救援
第二驾驶员

AI推荐
```

### 方案三：安心型

```text
沃尔沃XC60或同级
总价：5,980元

包含：
低免赔额
不限里程
上门送取
轮胎与玻璃保障
24小时救援
```

# 九、报价详情展开页

用户点击“查看价格明细”后，显示：

```text
车辆租金                 ¥3,150
保险保障                 ¥520
异地还车                 ¥300
送车服务                 ¥80
附加驾驶员               ¥100
节假日供需调整           ¥280
会员优惠                -¥150
--------------------------------
预计总价                 ¥4,280
```

还要明确显示：

* 押金多少
* 是否到店支付
* 是否可能产生额外费用
* 油量政策
* 取消规则
* 超时规则
* 超里程规则
* 违章处理规则

# 十、让页面更智能的功能

## 1. “为什么推荐这辆车”

例如：

> 推荐理由：
> 4人长途出行、携带两个大行李箱，且川西部分道路海拔较高。中型SUV在空间、通过性和价格之间更平衡。

---

## 2. 一键修改条件

在报价结果旁边直接提供：

* 换更便宜车型
* 增加保险
* 改成不限里程
* 取消上门送车
* 改变租期
* 查看新能源车

用户点击后即时重新报价。

---

## 3. AI价格优化建议

例如：

> 将取车时间从周五晚改为周六上午，预计可节省180元。

> 延长一天后触发7天套餐，反而只增加60元。

这种功能会明显提高产品价值。

---

## 4. 报价可信度

建议显示：

```text
报价置信度：高
库存更新时间：2分钟前
价格有效期：30分钟
```

如果库存或供应商价格不稳定，应显示：

```text
当前为预估价，最终价格需供应商确认
```

# 十一、后台需要保存哪些数据

建议至少保存：

* 用户原始需求
* AI解析后的结构化需求
* 每次报价结果
* 报价所使用的规则版本
* 报价时间
* 用户点击的方案
* 用户修改过的条件
* 最终是否下单
* 实际成交价格
* 取消原因
* 额外费用
* 用户反馈

这样以后才能训练和优化报价模型。

---

# 十二、MVP第一版不要做得太复杂

第一版建议只做：

1. AI收集租车条件
2. 调用车辆库存
3. 输出三套报价
4. 显示价格明细
5. 支持调整车型、保险和里程
6. 生成报价单
7. 人工确认后成交

第一版不要直接做完全动态定价。先使用：

```text
规则引擎 + 固定价格表 + AI解释
```

积累订单后，再加入：

* 实时供需定价
* 成交概率预测
* 用户价格敏感度
* 利润最大化推荐
* 风险评分

---

# 十三、最合理的产品定位

不要把它定位成：

> 会聊天的租车客服

而应该定位成：

> **懂行程、懂车辆、懂风险、会比较价格的租车决策助手。**

真正的竞争力不只是“报多少钱”，而是同时回答：

* 为什么是这个价格
* 为什么推荐这辆车
* 有没有更省钱的选择
* 有哪些隐藏风险
* 最终需要支付多少
